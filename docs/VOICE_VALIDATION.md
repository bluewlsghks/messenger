# 음성통화 검증 기록

## 2026-10-06 후속 수정

- WebRTC의 빈 ICE candidate는 end-of-candidates 신호이므로 정상 전달하도록 DTO/서비스 검증을 수정했습니다. 공백만 있는 잘못된 후보는 계속 거부합니다. 서버와 브라우저 회귀 테스트를 각각 추가했습니다.
- 브라우저 로그인 테스트의 버튼 선택을 `get_by_role('button', name='로그인', exact=True)`로 명시했습니다.
- 음성 브라우저 실패 시 HTTP 상태·명령 종류·페이지 및 연결 상태를 아티팩트에 남기도록 보강했습니다. 인증 헤더·SDP·ICE 주소·마이크 데이터는 기록하지 않습니다.
- 로컬 Node 22에서 신규 음성 회귀 테스트 **17개 통과**, 브라우저 테스트 Python 문법 확인.
- 최초 기능 커밋 `a5d782b`의 CI [37397735570](https://github.com/bluewlsghks/messenger/actions/runs/37397735570): Java 71개·JavaScript 35개·기존 작업 화면 브라우저 시나리오 10개 통과. 새 음성 브라우저 시나리오는 실패했으므로 이 결과로 실제 양방향 통화 검증 완료를 주장하지 않습니다.
- 후속 소스에는 음성 Java 테스트 16개와 음성 JavaScript 테스트 17개, 음성 브라우저 시나리오 8개가 있습니다. 후속 전체 실행 결과는 PR #2의 해당 커밋 CI로 확인합니다.

가상 마이크의 RTP 패킷 테스트와 실제 기기 음질·외부망/TURN·모바일 백그라운드 검증은 별개입니다. 기능별 실행 조건은 [VOICE_CALLS.md](VOICE_CALLS.md), 사용자용 기능 및 검증 요약은 루트 [README](../README.md)에 유지합니다.
