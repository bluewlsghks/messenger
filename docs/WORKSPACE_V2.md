# Messenger Workspace v2

개발 브랜치: `feat/discord-server-channels`, PR #1. master 병합, 배포 및 운영 DB 변경은 수행하지 않았다.

## 친구 목록 오류

JWT 필터의 principal은 문자열인데 FriendController는 `@AuthenticationPrincipal(expression="username")`으로 존재하지 않는 속성을 읽었다. 목록/추가/삭제를 Principal → ChatAccessService.actor() 방식으로 통일했다. 실제 JWT HTTP 통합 테스트 및 브라우저 로그인 후 친구 목록/추가/DM으로 검증한다.

친구 이름 일괄 조회, 중복 관계 표시 제거, 잘못된 과거 선택적 날짜 값에 영향을 받지 않는 관계 ID 조회, 존재하지 않는 사용자·자기 자신 추가 거부, 재시도 가능한 upsert, 친구 삭제 확인을 추가했다. 친구 삭제는 기존 DM 내역을 지우지 않는다. 전화번호가 없는 사용자의 프로필 조회에서 null 값 때문에 발생하던 오류도 수정했다.

친구 정책은 기존과 같은 **상호 즉시 등록**이다. 수락/거절/차단은 아직 없다. 양방향 관계는 두 개의 재시도 가능한 쓰기이며 하나의 다중 문서 트랜잭션은 아니다.

## 화면과 대화 기능

홈/친구/DM/서버를 하나의 작업 화면으로 통합했다. 서버 레일, DM/채널 사이드바, 대화 영역, 선택적으로 여는 멤버 패널을 제공한다. 다크/라이트 테마, 로그인/가입 화면, 모바일 사이드바, Ctrl+K 탐색, 오류/빈 목록 상태를 추가했다. 멤버 패널은 실제 참여자 목록이며 가짜 온라인 상태를 표시하지 않는다.

새 작업 화면은 로컬 CSS 및 WebJar의 STOMP/SockJS를 사용한다. 최초 Gradle 빌드에는 의존성 다운로드가 필요하지만 화면에서 외부 CDN을 호출하지 않는다. 서버 데이터와 사용자 입력은 textContent로 렌더링한다.

자신의 메시지 수정/삭제, 수정 표시, 실시간 변경, 검색, 복사, 기본 이모지, 글자 수, 대화별 초안을 추가했다. 수정/삭제는 작성자 및 참여 권한을 확인하고 version 조건부 갱신을 사용한다. 예전 버전의 요청은 409를 반환한다. 삭제 시 본문을 비우고 deletedAt을 남긴다. 백업 및 이미 받은 외부 기기의 복사본까지 제거하지는 않는다.

검색은 현재 대화 범위, 문자 그대로의 검색어 최대 100자, 최신 50개 결과, DB 실행 시간 제한을 적용하며 삭제된 메시지를 제외한다. 초안은 사용자+대화별 브라우저 저장소에 보관하고 로그아웃 시 제거한다. IME 조합 중 Enter 방지, Shift+Enter 줄바꿈, 실제 보이는 메시지 읽음, 과거 커서 조회, 새 메시지로 이동 버튼을 제공한다. 자동 재전송/중복 저장 방지용 멱등 키는 아직 없다.

## 알림

메시지 저장 → MessageNotificationListener → ConversationEvents가 실제 멤버 조회 → 사용자별 `/user/queue/events` → 대화/배지/팝업 갱신.

현재 열어 둔 채널 외의 DM·그룹·서버 채널도 수신한다. outbound 인터셉터에서 JWT, 수신자 및 현재 채널 참여 권한을 재확인한다. 자신이 보낸 메시지, 수정/삭제, 현재 보고 있는 대화에는 새 메시지 팝업을 중복 표시하지 않는다. 대화별 음소거는 팝업과 소리만 끄고 배지는 유지한다.

설정: 좌측 아래 톱니바퀴 → **데스크톱 알림 허용** → 브라우저 권한 허용. 앱 안 팝업, 소리, 본문 미리보기는 각각 설정할 수 있다. 데스크톱·소리·본문 미리보기는 기본 꺼짐이며 설정은 사용자별 해당 브라우저에 저장한다.

알림의 한계:
- HTTPS 또는 localhost 및 브라우저 지원/권한이 필요하다. 외부 IP의 일반 HTTP에서는 제한될 수 있다.
- **탭/브라우저를 닫은 상태의 Web Push, 서비스 워커, 네이티브 백그라운드 푸시는 미구현이다.** 연결된 작업 화면이 열려 있는 동안 수신한다.
- OS 방해 금지/알림 차단/절전은 앱이 해제하지 않는다.
- 소리는 사용자 동작이 필요하며 새 탭/접속에서 다시 활성화해야 할 수 있다.
- 여러 탭 시스템 팝업은 Web Locks로 조정한다. 미지원 브라우저의 대체 처리는 동시 중복을 완전히 보장하지 않는다.
- 알림 센터는 이번 접속의 최근 50개 이벤트이며 기록 비우기는 읽음/삭제가 아니다.
- 배지는 DB readBy에서 현재 접근 가능한 방만 집계하므로 새로고침해도 유지된다.
- 온라인 이벤트 발행은 best-effort다. 영속 outbox와 완전한 오프라인 재생은 아직 없다.

## 검증과 적용

Java 단위/실제 MongoDB HTTP 통합 테스트, Node 회귀 테스트, Chromium 다중 계정 E2E를 실행한다. HTTP·MongoDB·JWT·STOMP는 실제 경로를 사용한다. **OS Notification 생성자/권한 응답 및 일부 백그라운드 상태는 기록용 객체로 대체한다. 실제 OS 팝업이 화면에 그려지는 것까지 검증하지 않는다.** 운영 TLS/프록시/부하 및 실제 OS 알림은 별도 확인이 필요하다.

CI 아티팩트 `messenger-validation`에 보고서, 브라우저 스크린샷, 실패 진단 및 테스트 소스가 포함된다. 커밋별 성공 여부는 GitHub Actions에서 확인한다.

현재 작업을 커밋/보관한 뒤:

```powershell
git fetch origin
git switch feat/discord-server-channels
git pull --ff-only origin feat/discord-server-channels
.\gradlew.bat test bootJar
.\gradlew.bat bootRun
```

로컬 브랜치가 없으면 `git switch --track origin/feat/discord-server-channels`. 서버 재시작 및 브라우저 새로고침이 필요하다. MONGODB_URI, APP_AES_KEY_BASE64, APP_JWT_SECRET_BASE64와 APP_ALLOWED_ORIGINS는 기존 설정을 사용한다. 우선 개발 DB에서 확인하고 **기존 암호화 데이터의 AES 키는 유지한다.** 기존 인덱스/사용자 ID 대소문자 적용 주의는 DISCORD_MVP.md를 참고한다.

음성/영상/화면 공유, 파일 첨부, 세부 역할/권한, 멘션/답장, 온라인 상태, 친구 승인/차단, 서버 탈퇴/강퇴/삭제, 토큰 폐기/회전, 영속 멱등 재전송, 대규모 부하/운영 보안 검증은 이번 범위에 포함하지 않았다.
