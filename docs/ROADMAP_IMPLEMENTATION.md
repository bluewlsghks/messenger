# README 후속 과제 구현 (2026-10-06)

원본: `4ffa27f`. 기존 사용자·메시지와 도메인 매핑을 유지하며, 다음 기능을 추가했습니다. 이 문서는 코드 범위이고 **실행 결과는 ROADMAP_VALIDATION.md**, 외부 기능의 준비는 **OPERATIONS.md**에서 확인합니다. 실제 배포·유료 서비스 구매·사용자 DB 초기화는 하지 않습니다.

## 전달 신뢰성과 읽음

현재 UI는 전송 의도를 `clientRequestId` UUID로 보관합니다. 동일 사용자/UUID의 부분 고유 인덱스와 원본 요청 지문으로 재시도를 판별합니다. 같은 ID/다른 본문·방·부모·첨부 조합은 409입니다. 재전송은 이미 수정/삭제된 메시지의 현재 상태를 반환하고 AI 요청을 다시 시작하지 않습니다. 오래된 클라이언트가 ID를 생략하는 경로는 기존 호환용이며 그 클라이언트의 재전송 멱등성을 보장하지 않습니다.

메시지 문서 자체의 `publicationPending` 필드를 본문과 **한 번의 MongoDB 원자적 쓰기**로 저장합니다. 다른 컬렉션의 outbox에 이중 쓰기하는 방식이나 replica-set 트랜잭션을 요구하지 않습니다. 워커는 임대 토큰/버전으로 해당 메시지를 발행하고 같은 버전일 때만 완료 처리합니다. 브로커·검색/Push 투영 실패 시 재시도합니다. 발행 후 완료 기록 전에 종료되면 재발행되므로 at-least-once이며, 클라이언트는 ID/버전으로 병합합니다. **브로커 제출 성공은 모든 브라우저 수신 확인과 같지 않습니다.**

`GET /api/messages/{roomId}/sync?afterId=…&limit=100`을 끝까지 반복해 장기 오프라인 구간을 대조합니다. 100은 페이지 크기이지 전체 복구 한도가 아닙니다. 수정·소프트 삭제의 현재 상태도 포함합니다. 모든 편집 중간 이력을 영구 저장/재생하는 이벤트 소싱은 아니며, 권한을 잃은 대화는 재생하지 않습니다. UI는 마지막 1,000개 객체의 가상 창을 유지하고 이전 내역은 기존 커서 API로 다시 읽습니다. 브라우저가 완전히 오프라인인 동안 읽을 수 있는 로컬 메시지 캐시는 만들지 않았습니다.

읽음 계산은 `messages.readBy`로 통합했습니다. 기존 `/api/dm` 읽음 경로도 동일 모델을 갱신합니다. 과거 `read_cursors` 문서는 호환/보존을 위해 남기며 DB를 삭제하지 않습니다.

## 커뮤니티와 권한

새 친구 관계는 요청/수락 절차입니다. 기존 상호 친구는 유지합니다. 요청 취소·거절, 차단/해제를 지원하며 차단은 새 친구 요청·DM 작성·1:1 통화를 제한합니다. 공유 서버의 과거 메시지를 삭제하거나 상대가 작성한 모든 서버 메시지를 숨기는 기능은 아닙니다.

소유자/관리자/일반 멤버, 강퇴·재참여 차단·해제, 소유권 이전·탈퇴·서버 소프트 삭제, 기존 초대 일괄 철회를 지원합니다. 초대 epoch와 서버 버전 조건부 갱신으로 오래된 초대/동시 변경을 처리합니다. 채널별 readers/writers는 `null`이면 모든 서버 멤버, 빈 배열이면 소유자만, 나머지는 지정 사용자만입니다. 쓰려면 읽기 권한도 필요합니다. REST, 파일 다운로드, 검색, STOMP 실제 전달에서 다시 검사합니다.

온라인 표시는 탭별 MongoDB lease(75초)와 heartbeat(25초), 입력 중 표시는 6초 만료로 관리합니다. 갑작스런 네트워크 단절은 즉시가 아니라 lease 만료 후 오프라인이 될 수 있습니다. UI는 상태를 4초마다 조회하며 DB가 온라인/오프라인의 유일한 즉시 진실이라는 뜻은 아닙니다.

## 첨부·답장·스레드·멘션

첨부는 GridFS, 파일당 10MiB, 메시지당 5개, 계정당 100MiB입니다. PNG/JPEG/WebP/PDF/UTF-8 텍스트의 서명/형식을 검사하고 실제 다운로드는 인증된 attachment 응답으로 제공합니다. 브라우저가 임의 HTML을 실행하도록 인라인 공개하지 않습니다. 이름/경로를 정리하며 업로드한 사용자와 방을 검증합니다. 멀웨어 검사/이미지 전체 재인코딩을 제공하는 것은 아니므로 신뢰할 수 없는 파일을 열지 않아야 합니다.

전송 전 파일 삭제와 메시지 첨부 claim은 경쟁을 방지합니다. 실패한 전송이 claim한 파일/소프트 삭제 후 보관 파일은 임의로 삭제하지 않습니다. 용량 정비는 백업 후 별도 보존 정책이 필요합니다. 용량 계수·GridFS 파일·청크는 여러 문서이므로 프로세스가 업로드 중 갑자기 종료되면 quota/고아 청크 정비가 필요할 수 있습니다.

부모 메시지와 방이 같아야 답장할 수 있습니다. 루트 ID에 따라 스레드를 묶고 페이지별로 조회합니다. 멘션은 현재 참여자의 `@아이디`만 기록합니다. UI는 답장/스레드와 첨부를 표시하며 기존 일반 메시지 포맷도 읽습니다.

## 음성·영상·화면 공유

DM 1:1 통화 외에 GROUP/서버 채널에서 **최대 4명 WebRTC mesh**를 제공합니다. 각 브라우저가 나머지 참여자와 직접 연결하므로 대규모 Discord형 SFU가 아닙니다. 카메라 또는 화면 공유 중 한 영상 소스를 선택합니다. 음소거·나가기·장치 변경, SDP 이전 ICE 버퍼, 중복 협상 억제, 연결 실패 시 제한된 ICE restart를 구현했습니다.

1:1·다인 참여를 같은 사용자 점유 맵으로 관리하고, 짧은 lease·콜/탭 검증·만료 정리로 중복 참여를 제한합니다. 상태는 MongoDB CAS 문서로 공유하며 **최대 64개 활성 세션**, 상태 문서 최대 4MiB로 제한합니다. 미디어 이벤트의 단기 송신 큐도 포함합니다. 이는 무제한 확장 설계가 아니라 소규모 다중 인스턴스 구현입니다.

**개인정보 처리 변경:** 실제 음성/영상은 서버에 녹음·저장하지 않습니다. 재시작/다중 인스턴스 처리를 위해 통화 메타데이터 및 짧게 대기하는 SDP/ICE가 기존 AES-GCM 키로 암호화되어 MongoDB에 임시 저장됩니다. 개별 신호는 짧게 만료되며 저장 문서는 24시간 TTL입니다. 키를 공유하는 서버는 복호화할 수 있으므로 사용자 신원 기반 E2EE라고 표현하지 않습니다. 통화 이력은 참여자·방·시각·종료 상태를 30일 보관하며 본인 참여 이력만 조회합니다.

마이크/출력 장치 선택과 선택적 벨소리를 제공합니다. 출력 장치 선택은 브라우저 `setSinkId` 지원에 따라 다릅니다. 1:1 통화 중 브로커 재연결에 30초 유예가 있으며 재연결/새로고침은 상태/탭 검사를 거칩니다. 웹앱이 완전히 종료된 상태에서는 Web Push 알림을 눌러 웹앱을 다시 열어 수락해야 합니다. 앱 종료 중 마이크를 자동으로 켜거나 OS 전화 앱처럼 통화를 수신하지 않습니다.

TURN 설정은 공용 STUN과 분리했습니다. `VOICE_RELAY_ONLY=true`는 TURN이 없으면 시작을 거부합니다. 실제 NAT/회사망/모바일망, iOS/Android/Safari, 화면 선택 UI·물리 장치 음질은 별도 실기기 확인이 필요합니다.

## 인증과 보안

새 로그인은 15분 access JWT + HttpOnly/SameSite=Strict refresh cookie를 발급합니다. refresh는 7일 절대 수명, 회전 CAS, 유효했던 구 토큰 재사용 시 세션 폐기, 기기 세션 목록/폐기를 제공합니다. 무작위 비밀값 추측만으로 다른 사람의 세션을 폐기하지 않습니다. 세션 ID는 HTTP/STOMP 전달 시 재확인합니다. 기존 sid 없는 액세스 토큰은 원래 만료까지만 호환합니다.

Cookie 인증을 사용하는 refresh/logout은 `X-Requested-With`와 요청 Origin 검사를 추가했습니다. 로그인·가입·일반 API·파일·STOMP 메시지에 DB 기반 사용자/IP 예산을 적용합니다. 프록시 헤더를 무조건 신뢰하지 않으므로 공개 터널 뒤에서는 IP 예산을 여러 방문자가 공유할 수 있습니다. 보안 게이트웨이·봇 방어·계정 복구는 별도 운영 범위입니다.

입력 ID/이름·비밀번호 정책을 보강하고 기존 전화번호 비수집을 유지합니다. 중복 ID/레거시 평문 필드는 값이 아닌 건수로 감사합니다. 고유 인덱스 충돌이 있으면 시작을 거부하고 데이터는 자동으로 삭제/정규화하지 않습니다.

Spring Boot 4.1.1/Java 21로 플랫폼을 갱신했습니다. REST/STOMP JSON 호환을 위해 Boot의 Jackson 2 호환 모듈을 명시적으로 사용하며, 이것은 향후 Jackson 3 전환까지의 연결 단계입니다. Web Push의 사용하지 않는 오래된 async-http-client/BC15on 전이를 제외했습니다. 실제 resolved runtime 좌표를 OSV에 질의하는 스크립트/CI를 추가했습니다. 검색 서비스 오류는 검사 완료/취약점 없음으로 처리하지 않습니다. 취약점 DB 결과가 깨끗해도 침투 테스트나 보안 감사 완료를 뜻하지 않습니다.

## 운영·검색·공개 터널

선택적 RabbitMQ STOMP relay는 사용자 registry와 미해결 개인 메시지를 서버 간 공유합니다. room/recipient 정보는 native headers로 전달되며 각 인스턴스가 수신 세션의 현재 권한을 확인합니다. 기존 `/sub/chat` 구독은 표준 `/topic/chat`으로 변환합니다. Sticky session은 HTTP API에 필요하지 않지만 SockJS fallback을 로드밸런싱할 때는 연결 단위 라우팅을 보장해야 합니다.

Actuator 최소 health는 공개, 나머지 metrics/운영 API는 32바이트 이상 별도 `APP_OPERATIONS_TOKEN`으로 보호합니다. 일반 JWT 사용자는 운영자가 아닙니다. 백업은 writer 중지 확인과 비밀 URI 임시 설정 파일, 복구는 **다른 새 DB만** 허용합니다. 세션/Push/일시 미디어 상태는 백업/복구에서 제외합니다. 원격 URI는 명시 옵션이 필요하고 실제 운영 복구 전 데이터 검증이 필요합니다.

Elasticsearch는 optional projection입니다. ngram(2~3) 분석기로 한국어/영어 부분 검색을 지원하고 버전 기반 갱신/삭제 tombstone으로 오래된 재시도의 복원을 막습니다. 검색 결과는 MongoDB 현재 본문/삭제/방 권한으로 재검증합니다. 서비스 장애/짧은 검색어에는 MongoDB로 대체합니다. 인덱스는 eventually consistent이며 동기화 중 일부 신규 검색 결과가 늦게 나타날 수 있습니다. 기존 메시지는 운영자 재색인으로 추가합니다. Elasticsearch 원본/권한을 신뢰하지 않습니다.

공개 터널은 별도 guardian 프로세스가 이번 앱/자식 프로세스의 PID와 시작 시각을 감시합니다. 앱 프로세스만 강제 종료한 경우도 해당 자식 터널을 정리합니다. guardian 자체·OS 전체가 종료되거나 프로세스 식별 정보를 제공하지 않는 환경까지 보장하지 않습니다. Quick Tunnel이 고정 주소나 PC를 꺼도 실행되는 서버로 바뀌지는 않습니다.
